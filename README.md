# Анализатор диалогов Капитана Крылова

Скрипт читает сообщения из SQLite за последние `ANALYSIS_DAYS` дней, группирует их по `chat_id`, отправляет один аналитический запрос в GigaChat API и сохраняет отчет в формате Markdown.

## Установка

Требуется Python 3.10 или новее. Все команды выполняются из каталога проекта:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp -n .env.example .env
```

Относительные пути из `.env` разрешаются относительно каталога проекта, поэтому запуск из другого рабочего каталога также поддерживается. Файл базы данных не входит в репозиторий: поместите его в каталог проекта или укажите путь в `DB_PATH`.

## Настройка GigaChat

Заполните `.env`:

```dotenv
DB_PATH=db.sqlite3
ANALYSIS_DAYS=7
PROMPT_PATH=PROMPT.md
GIGACHAT_CREDENTIALS=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
GIGACHAT_VERIFY_SSL=true
GIGACHAT_TOP_P=0.1
GIGACHAT_TEMPERATURE=0.3
GIGACHAT_MAX_TOKENS=4000
```

`GIGACHAT_CREDENTIALS` — Base64-строка учетных данных из кабинета GigaChat, без префикса `Basic`. Для корпоративного контура выберите соответствующий `GIGACHAT_SCOPE`.

Проверка TLS включена по умолчанию. `GIGACHAT_VERIFY_SSL=false` следует использовать только для временной диагностики соединения. URL OAuth и API, таймаут и параметры повторных запросов заданы в `main.py`.

## Запуск

```bash
.venv/bin/python main.py
```

Дополнительные параметры командной строки:

```bash
.venv/bin/python main.py \
  --days 40 \
  --db-path db.sqlite3 \
  --output report_test.md
```

- `--days`: период анализа, положительное целое число;
- `--db-path`: путь к SQLite;
- `--output`: точное имя выходного файла.

Без `--output` создается `report_dd_mm_YY.md` в каталоге проекта. Файл сначала записывается во временное имя и затем атомарно заменяется. Если диалогов за период нет, GigaChat не вызывается, а создается отчет с нулевой статистикой.

## Обработка запросов и логирование

Содержимое `PROMPT_PATH` передается модели отдельным системным сообщением. Подготовленные диалоги передаются вторым сообщением с ролью `user`. Дополнительные инструкции к промпту в коде не добавляются, повторный анализ ответа модели не выполняется.

Для получения токена и запроса на анализ предусмотрены три повторные попытки при HTTP 429, 500, 502, 503 и 504. Таймаут каждого HTTP-запроса — 60 секунд, задержка перед повтором — случайное значение от 3 до 10 секунд. Ход загрузки, HTTP-запросы, повторы, ошибки и путь к отчету выводятся в журнал.

## Формат сообщений в базе

Поддерживаются типы отправителей `human` и `ai` в любом регистре. Скрипт нормализует их перед группировкой. Другие значения отклоняются с понятной ошибкой, чтобы не исказить анализ.
